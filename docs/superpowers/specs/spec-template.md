方案选择 / 验收条件**四节必须保留。

## 4. 仓库结构

```text
packages/<name>/
├─ src/
│  ├─ index.ts       公共出口:只导出稳定 API
│  ├─ api/           领域模块(收藏夹 / 关系 / 评论...)
│  ├─ types.ts       核心接口与枚举(字段语义的权威定义)
│  └─ errors.ts      统一错误类 + 错误码
├─ tests/            Vitest 测试(真实协议路径优先)
├─ package.json      版本 / exports / scripts
└─ README.md         安装方式 / API / 参数表 / 错误码
```

## 6. 错误处理

| 错误码 | 含义 | 上层提示 |
| --- | --- | --- |
| `LOGIN_REQUIRED` | 需要登录 | 请先扫码登录 |
| `NETWORK` | 网络失败 | 检查网络 |

## 7. 测试策略

- 真实协议路径(本地 mock 服务器 / 真实 API 冒烟)。
- 错误分支覆盖(登录失效 / 网络 / 超时 / 参数非法)。
- 写操作自清理(测试结束恢复现场)。

## 8. CLI 与 skill 同步

- 是否暴露到 CLI?新增/改名/删除哪些命令?
- 对应 `skills/<name>-cli/SKILL.md` 需要更新什么(命令 / 参数 / 对照表)?
- (提交守卫会自动拦命令集不一致,但参数/语义需人工检查。)

## 9. 版本与发布

- 版本 bump 规则(patch / minor / major)。
- 是否触发 CI 发布;发布后跑 `pnpm verify:published <包名>`。

## 10. 验收条件

- [ ] 功能可用(最小示例跑通)
- [ ] 测试全绿(含错误分支)
- [ ] 文档更新(README + packages-index)
- [ ] skill 已同步(若涉及 CLI)
- [ ] `pnpm check` 通过
- [ ] 用户确认后提交推送,CI 发布成功,消费验证通过
