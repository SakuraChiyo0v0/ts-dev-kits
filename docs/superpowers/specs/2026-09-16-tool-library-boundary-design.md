# 纯工具库边界调整

## 目标与授权

用户已确认：先用备份分支保存应用和宿主适配，再把主分支整理为发布到 GitHub Packages、供其他项目复用的纯工具库；暂不建立独立仓库。不执行远端推送、发布或 NAS 操作。

## 方案

保留 20 个工具包的 API、版本和源码。两个应用、DSH 适配包、专属部署流程及文档保存在备份分支；含忽略文件的目录额外移到本地备份。相比立即拆分多个仓库，此方案不新增维护负担且保留恢复路径。

## 任务

- 建立并核实备份分支与当前提交一致。
- 移出应用、宿主适配和专属工作流。
- 更新 workspace、lockfile、构建、发布清单、hook、CI 和文档。
- 新增边界守卫，检查应用回流、发布漏包及依赖顺序。
- 全仓构建、类型、测试、CLI 检查；记录既有问题与未验证范围。

## 验收

主分支只含工具包，20 个包全部进入发布清单；备份可恢复；安装锁文件与 workspace 一致；不触发外部发布。公共 API 和错误码不改变，无需本次统一 bump 工具包版本。
